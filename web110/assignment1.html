The first lesson I learned was to include a README.md file within my repository. This document allows me to specify the website title, provide a description, outline the main features, and offer instructions for use. It also includes details such as the technologies used (HTML, CSS, and JavaScript), acknowledgments for resources used, licensing information specifying how the website may be used, and my credentials. The second lesson I learned was that an Index.html file is the main page of a website; it contains all of the HTML coding that structures the website and its contents (such as headings, paragraphs, images, buttons, and links). For example, an index.html file might tell the browser to display a shopping cart button, and when clicked, it redirects you to the store of the website or, more commonly, to the user's shopping cart, where the items they are seeking to purchase will again be displayed in image or text format by the Index.html file. The third lesson I learned was how different files connect, allowing HTML, CSS, and JavaScript to work together effectively, and I learned how to make a folder and what its uses are, such as organizing files, allowing you to keep related files together, and keeping projects structured instead of having every file bunched up. Folders make file seeking and management easier as a project increases in size, like within larger websites/projects, which may have folders with labels like CSS for styling files, JS for JavaScript files, and Assets for other resources. When the website needs a file from within a folder, the HTML can use the file path, like images/logo.png. So, in short, folders help keep things clean and make it easier for you to work on files and for files to work together /p>
